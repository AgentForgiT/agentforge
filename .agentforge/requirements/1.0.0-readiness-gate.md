## Purpose

The 0.1.0 gate (DEC-0006) defined the *adoptable* line; **1.0.0 defines the *stable* line**. 1.0.0 is the release where the API surface is frozen: breaking changes require a minor bump **and** an ADR from here on. This sprint audits readiness and ships 1.0.0 if every gate box is verifiable — exactly the DEC-0006 pattern.

## 1.0.0 Definition

1.0.0 is the **stability commitment**: the gateway surfaces, CLI commands, SDK API, AICS spec, and MCP methods are frozen for the 1.x line. Post-1.0.0, breaking changes require a minor bump and an ADR; the 0.x feature line ends.

## Audit Criteria (all must hold, each with evidence)

1. **Suites green offline**: gateway, CLI, SDK, benchmarks — full local suite + CI Bootstrap Validate.
2. **No Draft ADRs/DECs**: every entry in the decision register is Accepted.
3. **Docs complete**: gateway, CLI, SDK, AICS, MCP registration, compatibility, community — on the public site and in-repo.
4. **Distribution working**: SDK + CLI wheels attach to releases via the tag-gated publish workflow (automated).
5. **AICS Level-3**: the AgentForge repo validates at Level 3 in CI.
6. **API-surface inventory**: a statement of what 1.0.0 freezes (surfaces, commands, SDK methods, AICS version, MCP methods) — the backward-compatibility contract.
7. **Release note**: RELEASE-1.0.0.md records the transition and DEC-0009.

## Acceptance Criteria

- [ ] Requirements doc + DEC-0009 land
- [ ] Audit produces evidence for each box (or an explicit deferral with a decision)
- [ ] API-surface inventory written
- [ ] RELEASE-1.0.0.md written; 1.0.0 tagged and released
- [ ] Publish workflow verified on the 1.0.0 tag
